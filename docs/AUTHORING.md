# Как добавить урок или задачу

Контент курса — это обычные JS-модули в `src/course/modules/`. Приложение ничего
не знает про конкретные уроки: оно рисует то, что описано в данных.

## Правила курса

- в уроке **ровно пять** задач;
- сложность растёт по постоянной схеме: `easy → easy → medium → medium → hard`;
- первая задача повторяет теорию, последняя — challenge без пошаговых указаний;
- у каждой задачи есть подсказки и рабочее решение;
- урок засчитывается, только когда решены все пять задач.

## Структура урока

```js
const lesson = {
  id: 'css-flexbox',              // уникальный, попадает в URL
  title: 'Flexbox',
  summary: 'Одномерная раскладка: направление, выравнивание, промежутки.',
  editors: ['html', 'css'],       // какие вкладки playground открыты
  sandbox: { /* см. ниже */ },    // необязательно
  theory: [ /* блоки, см. ниже */ ],
  starter: {                      // общий стартовый код для всех задач урока
    html: '<div class="row">…</div>',
    css: '.row { … }'
  },
  tasks: [ /* пять задач */ ]
};
```

Урок подключается в массив `lessons` своего модуля (`htmlModule`, `cssModule`,
`javascriptModule`, `projectModule`). Нумерация уроков и модуль проставляются
автоматически в `src/course/index.js`.

## Структура задачи

```js
{
  id: 'css-flexbox-3',            // уникальный по всему курсу
  title: 'Идеальное центрирование',
  difficulty: 'medium',           // easy | medium | hard
  description: 'Поставьте элементы по центру…',   // поддерживает `код` и **жирный**
  starter: { css: '…' },          // перекрывает starter урока, только нужные файлы
  sandbox: { storageSeed: { … } },// перекрывает sandbox урока
  checks: [ … ],
  hints: ['Первая подсказка', 'Вторая — конкретнее'],
  solution: { css: '…' }          // тоже только изменённые файлы
}
```

`starter` и `solution` доливаются поверх значений урока, поэтому в задаче пишут
только то, что действительно меняется.

## Блоки теории

```js
theory: [
  { lead: 'Вводный абзац покрупнее' },
  { h: 'Подзаголовок' },
  { p: 'Обычный абзац с `кодом`, **жирным** и *курсивом*' },
  { ul: ['пункт', 'пункт'] },
  { ol: ['шаг', 'шаг'] },
  { code: 'display: flex;' },
  { table: { head: ['Свойство', 'Смысл'], rows: [['gap', 'промежуток']] } },
  { note: 'Полезное замечание' },
  { warn: 'Частая ошибка' }
]
```

Текст экранируется, поэтому про `<a href>` можно писать спокойно.

## Конфигурация песочницы

```js
sandbox: {
  assets: DEMO_IMAGES,                       // 'photos/cat.jpg' → inline data-URI
  mockApi: {
    '/api/users': { json: [...], delayMs: 80 },
    '/api/missing': { status: 404, json: { error: 'not found' } }
  },
  storageSeed: { draft: 'недописанная заметка' },  // предзаполненный localStorage
  modules: { './math.js': 'export const add = …' },// виртуальные ES-модули
  promptAnswers: ['42'],                     // что вернут prompt()/confirm()
  allowNetwork: false                        // по умолчанию сеть закрыта
}
```

Настоящая сеть отключена: если адрес не описан в `mockApi`, `fetch` отклоняется с
понятным сообщением. Так уроки работают офлайн и всегда одинаково.

## Типы проверок

У каждой проверки обязателен человекочитаемый `label` — именно он показывается
студенту.

### Разметка

| kind | Поля | Что проверяет |
|---|---|---|
| `exists` | `selector` | элемент есть на странице |
| `absent` | `selector` | элемента нет |
| `count` | `selector`, `equals` / `min` / `max` | количество элементов |
| `text` | `selector`, `equals` / `contains` / `matches` | текст элемента (пробелы нормализуются) |
| `html` | `selector`, `contains` / `matches` | разметка внутри элемента |
| `attr` | `selector`, `name`, `equals` / `contains` / `matches` / `exists` | значение атрибута |
| `noAttr` | `selector`, `name` | атрибута быть не должно |
| `prop` | `selector`, `name`, `equals` | свойство DOM-объекта (`value`, `checked`, `disabled`) |

### Стили

| kind | Поля | Что проверяет |
|---|---|---|
| `style` | `selector`, `prop`, `equals` / `contains` / `oneOf` / `min` / `max`, `pseudo` | вычисленный стиль |
| `cssRule` | `selector` или `selectorContains`, `prop`, `media` | само правило в таблице стилей |

`style` сравнивает то, что реально применилось: `blue` совпадёт с
`rgb(0, 0, 255)`. Для сокращённых свойств проверяйте longhand-и
(`border-top-width`, а не `border`). `cssRule` нужен там, где одного рендера не
хватает: `@media`-блоки, `:hover`, `transition`.

### Код

| kind | Поля | Что проверяет |
|---|---|---|
| `source` | `lang` (`html`/`css`/`js`), `contains` / `notContains` / `matches` | исходный текст студента |

Проверяйте исходник только тогда, когда результат не наблюдаем: «использован
`const`», «ответ не вписан вручную», «есть комментарий». Всё, что видно в DOM,
проверяйте по DOM.

### Поведение

| kind | Поля | Что проверяет |
|---|---|---|
| `console` | `contains` / `matches` | вывод `console.*` |
| `alert` | `contains` | аргументы `alert/prompt/confirm` |
| `noError` | — | в консоли нет ошибок |
| `storage` | `key`, `equals` / `contains` | запись в localStorage |
| `interact` | `steps`, `then` | состояние после действий пользователя |
| `custom` | `fn` | произвольная проверка |

Шаги `interact`:

```js
{ do: 'click',   selector: '#btn' }
{ do: 'type',    selector: '#name', value: 'Алиса' }   // + события input и change
{ do: 'check',   selector: '#agree', value: true }
{ do: 'select',  selector: '#plan', value: 'pro' }
{ do: 'submit',  selector: 'form' }
{ do: 'key',     selector: '#field', key: 'Enter' }
{ do: 'event',   selector: '#box', type: 'mouseenter' }
{ do: 'wait',    ms: 100 }
{ do: 'waitFor', selector: '.loaded', timeout: 2000 }
```

Каждая `interact`-проверка получает **свежую страницу**, поэтому пишите её как
самостоятельный сценарий с самого начала — состояние от предыдущих проверок не
переносится.

`custom` получает контекст и возвращает `true` либо строку с объяснением:

```js
{
  label: 'Карточка отцентрирована',
  kind: 'custom',
  fn: "const box = ctx.$('.card').getBoundingClientRect();" +
      "const right = ctx.doc.documentElement.clientWidth - box.right;" +
      "return Math.abs(box.left - right) < 3 || 'Слева ' + box.left + ', справа ' + right;"
}
```

В `ctx` доступны: `doc`, `win`, `$`, `$$`, `source` (`{html, css, js}`),
`console`, `alerts`, `errors`, `storage`, `text()`, `sleep()`. Тело `fn` — строка,
она компилируется как `async`-функция уже внутри песочницы.

### Общие модификаторы

- `any: true` — достаточно одного подходящего элемента (по умолчанию условию
  должны удовлетворять **все** найденные);
- `waitMs: 2000` — сколько ждать асинхронного результата (fetch, таймеры);
- `caseSensitive: true` — сравнивать с учётом регистра.

## Как писать хорошие проверки

- **Проверяйте результат, а не способ.** Ученик может расставить теги в другом
  порядке — это нормально, если итог верный.
- **Формулируйте `label` как факт**: «У всех ссылок есть `rel="noopener"`».
  Он показывается и при успехе, и при ошибке.
- **Сообщение об ошибке возвращайте с цифрами**: «Ширина 350px вместо 300px»
  полезнее, чем «неверная ширина».
- **Не завязывайтесь на ширину превью.** Панель может быть узкой — для проверок
  раскладки берите относительные величины или добавляйте порог по ширине.
- **Одна проверка — одна мысль.** Пять понятных строк лучше одной большой.

## Перед коммитом

```bash
npm run validate   # структура: пять задач, уникальные id, известные типы проверок
npm test           # плюс реальный прогон: решения проходят, стартовый код — нет
```

Если проверка не сходится, откройте `tests/selftest.html?lesson=<id>` в браузере:
на странице видно каждую проверку и причину, по которой она не прошла.

## Добавить перевод

Перевод — это **оверлей поверх базового контента**, а не его копия. Структура
урока, набор задач и условия проверок остаются в `src/course/modules/`;
перевод переопределяет только то, что читает студент.

### Куда что класть

Базовый язык контента задаётся константой `BASE_LOCALE` в `src/i18n/index.js`
— это язык, на котором написаны уроки в `src/course/modules/`, и запасной
вариант для непереведённых строк. Язык по умолчанию для нового посетителя —
отдельная константа `DEFAULT_LOCALE`.

| Что переводим | Файл |
|---|---|
| Интерфейс (кнопки, тосты, подтверждения) | `src/i18n/ui/<locale>.js` |
| Сообщения проверок | `src/i18n/sandbox/<locale>.js` |
| Сообщения `custom`-проверок | `src/i18n/sandbox/<locale>-phrases.js` |
| Уроки и задачи | `src/course/i18n/<locale>/<module>.js` |

### Формат перевода урока

```js
const lesson = {
  title: 'Havolalar',
  summary: '…',
  theory: [ /* те же блоки, что в оригинале */ ],
  starter: { html: '…' },        // общий стартовый код урока
  sandbox: { mockApi: { … } },   // если данные песочницы видны студенту
  tasks: {
    'html-links-1': {
      title: '…',
      description: '…',
      hints: ['…', '…'],          // столько же подсказок, сколько в оригинале
      starter: { html: '…' },     // если в стартовом коде есть видимый текст
      solution: { html: '…' },    // если в решении есть видимый текст
      checks: [                   // патчи по индексу, длина = числу проверок
        { label: 'Sahifada <a> havolasi bor' },
        { label: 'href google.com ga olib boradi' },
        null                      // null — оставить проверку как есть
      ]
    }
  }
};
```

Патч проверки может переопределить не только `label`, но и ожидаемое значение —
`equals`, `contains`, `matches`, `steps`, `fn`, вложенные `then`. Это нужно там,
где задача ждёт конкретную видимую строку: если в узбекской версии кнопка пишет
`Jami: 126 000 so‘m`, то и проверка должна ждать это, и решение — печатать это.

Менять в патче условие проверки (селектор, `kind`, пороги) не нужно: логика
должна быть одинаковой во всех языках, иначе задача станет разной по сложности.

### Сообщения custom-проверок

`custom`-проверки собирают текст ошибки сами. Чтобы не дублировать 177 функций,
локаль поставляет таблицу фраз:

```js
export const uzPhrases = [
  ['Ширина ', 'Kenglik '],
  ['px вместо 40px', 'px, 40px bo‘lishi kerak']
];
```

Harness применяет замены к готовому сообщению, начиная с самых длинных фрагментов.
Пробелы в начале и в конце значимы — они часть склейки.

Собрать список непереведённых фрагментов можно так:

```bash
node tools/translation-worksheet.mjs <moduleId> [fromLesson] [toLesson]
```

Скрипт печатает всё, что нужно перевести для модуля, в том порядке, в котором
это ждёт оверлей: тексты урока, задач, подсказки и каждую метку проверки вместе
с литералами, с которыми она сравнивает.

### Проверка перевода

```bash
npm run validate                      # покрытие + расхождения с оригиналом
node tools/run-selftest.mjs --locale=uz --from=4 --to=6
```

Валидатор ругается, если перевод отстал: в задаче стало больше проверок, чем
патчей, или подсказок меньше, чем в оригинале. Self-test прогоняет решения и
стартовый код каждой локали отдельно — именно он ловит ситуацию «условие
перевели, а решение осталось на другом языке».
