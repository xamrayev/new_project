# Web Development — интерактивный курс

Курс веб-разработки, в котором **каждый урок проходит внутри playground**: слева теория,
справа редакторы HTML/CSS/JS с живым превью, внизу — пять практических задач с
автоматической проверкой.

```

├─────────────┬──────────────────┬──────────────┬──────────────────────┤
│ ТЕОРИЯ      │ HTML  CSS  JS    │ LIVE PREVIEW │ ЗАДАЧИ         1/5   │
```

## Быстрый старт

```bash
npm start           # http://localhost:4173
```

Открывать `index.html` двойным кликом нельзя: ES-модули и загрузка песочницы
требуют http(s). Подойдёт любой статический сервер.

```bash
npm run validate    # структурная проверка курса (без браузера)
npm test            # валидация + прогон всех 170 решений в реальном браузере
```

### Один playground на весь курс

Отдельного редактора «для HTML» и «для CSS» нет. Есть один универсальный
playground, а урок через конфигурацию решает, что студенту доступно:

```js
{
  id: 'css-flexbox',
  editors: ['html', 'css'],          // какие вкладки открыты
  sandbox: {
    assets: DEMO_IMAGES,             // учебные файлы картинок
    mockApi: { '/api/users': { json: [...] } },
    storageSeed: { draft: '…' },     // предзаполненный localStorage
    modules: { './math.js': '…' }    // виртуальные ES-модули через import map
  }
}
```

### Панели

Рабочая область — шесть независимых панелей: **Теория**, **Код**, **Live
preview**, **Консоль**, **Задачи** и **Журнал**. У каждой в заголовке две
кнопки: развернуть на весь экран (`⛶`, выход по Escape) и закрыть (`✕`).
Закрытая панель не оставляет пустого места — `panes.js` пересобирает шаблон
сетки из того, что осталось открытым, и соседи забирают освободившуюся ширину.
Кнопка `▦` в шапке возвращает любую панель обратно; последнюю открытую закрыть
нельзя. Состояние панелей хранится вместе с прогрессом, поэтому рабочее место
восстанавливается после перезагрузки.

Шаблоны сетки пишутся в CSS-переменные (`--cols`, `--split-cols`,
`--right-rows`), а не в `style.gridTemplateColumns`: inline-стиль перебил бы
медиазапросы, а так на узком экране всё честно перестраивается в одну колонку.

### Консоль

Консоль — не выдвижная панель, а постоянная часть правой колонки под превью.
В неё попадают `console.log()`, предупреждения, необработанные ошибки и вызовы
`alert()` / `prompt()` / `confirm()` (перехваченные, чтобы не блокировать
проверку). Номер строки в ошибке — это строка **в редакторе**: harness вычитает
всё, что песочница добавила сверху.

### Журнал действий и кеш

Кнопка `📋` в шапке показывает, сколько действий записано, и по клику открывает
модальное окно со всей историей. Тот же журнал можно держать открытым как
отдельную колонку (панель «Журнал»).

Главное, что видно в журнале, — **откуда взялся код**:

| Запись | Когда появляется |
| --- | --- |
| `Код написан вручную` | студент печатает; подряд идущие нажатия склеиваются в одну запись |
| `Код вставлен (paste)` | `paste` или drag-and-drop — никогда не склеивается |
| `Показано готовое решение` | нажата кнопка «Показать решение» |
| `Код удалён`, `Запуск кода`, `Проверка`, `Открыта подсказка`, `Задача начата заново`, `Открыта задача` | остальные действия |

Записи хранятся в отдельном ключе `webdev-course:log:v1` (последние 400) и
содержат только идентификаторы и числа — поэтому смена языка переписывает всю
историю на новый язык, а не оставляет старые формулировки.

Блок «Кеш» в том же окне показывает размер каждой части хранилища и чистит их
по отдельности: журнал, сохранённый код задач, прогресс — или всё сразу.
Очистить журнал можно, не теряя прогресс, и наоборот. Рядом — выгрузка копии
всего кеша в JSON.

### Песочница

Код студента исполняется в `<iframe sandbox="allow-scripts …">` **без**
`allow-same-origin`, то есть на непрозрачном источнике: страница курса для него
недосягаема. Поэтому проверки выполняются не снаружи, а внутри песочницы —
`harness.js` получает описания проверок через `postMessage` и отвечает
результатами. Он же:

- перехватывает `console.*`, `alert/prompt/confirm` и ошибки → панель «Консоль»;
- подменяет `localStorage` рабочим shim'ом (на непрозрачном источнике настоящий
  недоступен) и синхронизирует его с хостом;
- обслуживает mock API: `fetch` отвечает данными урока, настоящая сеть закрыта —
  уроки работают офлайн и всегда одинаково.

### Проверки — данные, а не код

Задача описывает результат декларативно, поэтому проверку видно целиком:

```js
checks: [
  { label: 'На странице есть ссылка', kind: 'exists', selector: 'a' },
  { label: 'href ведёт на google.com', kind: 'attr', selector: 'a', name: 'href', contains: 'google.com' },
  { label: 'Цвет фона — #111827', kind: 'style', selector: 'body', prop: 'background-color', equals: '#111827' },
  {
    label: 'После клика текст меняется',
    kind: 'interact',
    steps: [{ do: 'click', selector: '#btn' }],
    then: [{ label: 'Текст обновился', kind: 'text', selector: '#output', equals: 'Welcome' }]
  }
]
```

Проверяется настоящий результат: DOM после исполнения, вычисленные стили
(`getComputedStyle`), содержимое `@media`-блоков из CSSOM, вывод в консоль,
состояние после клика, записи в localStorage, ответы mock API. Полный список
типов — в [docs/AUTHORING.md](docs/AUTHORING.md).

## Языки

Курс полностью доступен на русском и узбекском: интерфейс, теория, условия
задач, подсказки и текст проверок. Язык переключается в шапке, выбор
запоминается; при первом заходе берётся язык браузера, а если он ни с чем не
совпал — узбекский (`DEFAULT_LOCALE`).

Не путайте две роли: `DEFAULT_LOCALE` — это язык по умолчанию для нового
посетителя, а `BASE_LOCALE` — язык, на котором **написан контент**
(`src/course/modules/`) и который служит запасным вариантом для непереведённых
строк. Менять нужно первую константу.

Переводится три слоя, и каждый живёт отдельно:

| Слой | Где | Что внутри |
|---|---|---|
| Интерфейс | `src/i18n/ui/<locale>.js` | кнопки, заголовки, подтверждения, уведомления |
| Песочница | `src/i18n/sandbox/<locale>.js` | сообщения проверок; словарь уезжает в iframe вместе с конфигурацией |
| Контент | `src/course/i18n/<locale>/` | уроки: теория, условия, подсказки, метки проверок |

**Логика проверок при этом не дублируется.** Перевод контента — это оверлей: он
переопределяет только то, что читает студент, а сами проверки остаются в одном
месте (`src/course/modules/`). Там, где задача ожидает конкретную видимую строку
(`Итого: 126 000 сум`), перевод точечно подменяет и ожидаемое значение, и
стартовый код, и решение — но не условие проверки.

Сообщения, которые `custom`-проверки собирают сами («Ширина 350px вместо 300px»),
переводятся таблицей фраз (`src/i18n/sandbox/uz-phrases.js`): harness подставляет
перевод в готовое сообщение. Так 177 функций живут в одном экземпляре на все
языки.

`npm run validate` показывает покрытие перевода и ругается, если перевод отстал
от контента — например, в задаче стало на одну проверку больше, чем меток в
переводе.

## Прогресс

Прогресс, черновики кода и тема хранятся в `localStorage` под одним ключом
(`webdev-course:v1`), поэтому их легко посмотреть, выгрузить или сбросить
(кнопка «Сбросить прогресс» в боковом меню). Сервер и аккаунт не нужны.

## Тесты

`npm test` поднимает статический сервер, открывает `tests/selftest.html` в
Chromium и для каждой из 170 задач **в каждой локали** проверяет две вещи:

1. авторское решение проходит **все** свои проверки;
2. стартовый код проваливает хотя бы одну — иначе задача решается сама собой.

Второй пункт важен именно для перевода: если узбекская версия задачи ожидает
`Jami: 126 000 so‘m`, а решение осталось русским, тест это покажет.

Так контент не расходится с движком: сломанную проверку видно до того, как на неё
наткнётся студент.
